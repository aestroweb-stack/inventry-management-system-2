# MYRAA R21 — Optional Qdrant HNSW visual search

Apply over R20 only. Back up all seller workspaces and product photos before deploying. No stock, invoice, product, authentication or existing recovery limits are changed. Qdrant is a derived index; the existing per-seller SQLite inventory remains authoritative. With no Qdrant variables set, R20 exact search continues unchanged. This patch does not provision a server, activate an external service, or migrate images to object storage.

## Enable on Linux production (Railway or VPS)
1. Create a dedicated, private Qdrant deployment supporting the REST Query API, tenant payload indexes and on-disk HNSW (Qdrant 1.16+ recommended; check provider compatibility). Use authenticated TLS or a trusted private network, not a publicly exposed HTTP endpoint. Restrict network access; never send the write key to a browser. A managed service may incur charges. Official setup: https://qdrant.tech/documentation/tutorials-operations/secure-qdrant/ and https://qdrant.tech/documentation/manage-data/multitenancy/.
2. On the **existing app service** set these server environment variables (not in source or frontend):

```
VISUAL_QDRANT_URL=https://YOUR-PRIVATE-QDRANT-HOST:6333
VISUAL_QDRANT_API_KEY=<your server-side write key>
VISUAL_QDRANT_NAMESPACE=<unique stable random string for this deployment>
VISUAL_QDRANT_WORKER=1
VISUAL_QDRANT_WORKER_INTERVAL=120
```

Use a different namespace for production and staging. Keep the namespace stable across deployments. If using verified private HTTP instead of TLS, explicitly set `VISUAL_QDRANT_ALLOW_PRIVATE_HTTP=1`; do not use it on public networks. For semantic image recognition, configure the EXISTING private `VISUAL_AI_URL` and `VISUAL_AI_API_KEY` separately; without them the local color/layout encoder is used. No Gemini/Claude API call is added. Do not change the existing `DATABASE_URL` or persistent volume. Use one mounted seller workspace volume, Linux flock, and a single active index worker per shared filesystem. The optional worker runs in a daemon thread on the app host; it does not require a second Railway volume. It runs passes approximately every 120 seconds after the previous pass finishes. It batches 128 reference rows and can take much longer on a large catalog. Worker starts on application startup; Windows does not run the worker. Original photos stay on the existing volume; Qdrant receives derived vectors and pseudonymous seller/generation plus reference IDs only. Ensure your data-processing terms and access control allow sending these derived data to the chosen service.
3. Deploy, then open Visual Product Search. `index syncing; standard search available` means no complete published generation yet. `indexed search configured` indicates a complete locally recorded generation (not a real-time Qdrant health check). Inspect logs for `Visual background indexing will retry` or `Visual ANN unavailable`. Test two different sellers, matching accuracy and inventory values before enabling for live customers. Index building starts automatically after deployment and retries periodically. First build can be slow. No need to manually trigger a global scan. Disable by removing `VISUAL_QDRANT_URL` and setting `VISUAL_QDRANT_WORKER=0`, then redeploy. Existing data remains intact; derived remote vectors are not automatically deleted when disabling.

## Design and guarantees
- Shared collection per deployment namespace and encoder model, cosine HNSW config m=16, ef_construct=128, query hnsw_ef=128, disk-backed vectors/index. Qdrant may choose a plain search for small/filtered groups. Request shortlist >=100 references, exact cosine rerank of live seller-local cached vectors, deduplicate by design. Shortlist can miss designs, especially if many photos belong to one product; every ANN result is review-only, not an automatic confirmed match. Live stock always comes from existing inventory API.
- A randomly versioned SQLite manifest and triggers invalidate a published index when a catalog reference is added, replaced, removed or archived/restored. Build a new generation in bounded batches, verify remote count, publish only if revision unchanged; old generation cleanup is best effort. Mandatory seller and generation filters on count, query and delete; remote payload independently checked against authenticated seller DB, product/image IDs and local reference file metadata. No cross-seller reference matching. An incomplete, stale, empty, invalid or unavailable ANN result falls back to R20 exact search. A missing remote index is rebuilt on a worker pass. No image path or stock is taken from remote results.
- This first integration rebuilds the whole seller generation after reference changes; frequent edits can delay publication and cause exact fallback. The worker is serial across sellers; it is not a distributed queue, incremental CDC or a billion-scale ingestion pipeline. Small catalogs may be faster without Qdrant. Out-of-band image-file modifications are not a supported workflow; use inventory UI for changes. Crashes, old namespaces/models, failed cleanup and seller account removal can leave unreferenced derived vectors in Qdrant; retention/deletion reconciliation and provider backup policy need operational implementation before commercial scale. Do not expose the Qdrant collection to sellers. Existing 5,000-media recovery cap remains: do not remove it without a verified backup replacement.
- Missing photos cannot establish exact SKU/stock. Existing Master SKU/QR/manual reference import remains the fallback. No global shared catalog or external image collection is added. Keep private seller photos private. A licensed opt-in reference catalog, object storage, scalable backup/restore, incremental indexing and distributed load testing are later work. One billion vectors and seconds-level p95 latency are not tested or guaranteed.

## Test scope
Real SQLite databases and small generated test images with HTTP mock Qdrant: payload filters, identical reference IDs across sellers, mismatch rejection, stale/deleted reference invalidation, restore, remote outage, missing remote vectors, mutation during build, fallback and no configuration. Existing R20/R13/R16 tests included. Actual Qdrant HNSW search, Railway deployment, concurrent load, private SigLIP, Windows script and production-scale performance require separate tests. Local regression tests used a temporary barcode import stub (no barcode operations exercised).
